---
title: 常見錯誤
description: 按狀態碼整理的常見錯誤、原因和解決方法。
---

呼叫失敗時，先看 HTTP 狀態碼和回傳的 `message`，再對照下表排查。錯誤訊息會根據請求語言顯示為中文或英文。

## 401：金鑰問題

| 錯誤訊息   | 原因                                     | 解決方法                                              |
| ---------- | ---------------------------------------- | ----------------------------------------------------- |
| 未提供令牌 | 請求標頭裡沒有攜帶 API 金鑰              | 檢查是否設定了 `Authorization: Bearer YOUR_API_KEY`   |
| 無效的令牌 | 金鑰不存在、已過期、額度已用完或已被停用 | 到 [API 金鑰](/keys) 頁面檢查金鑰狀態，必要時重新建立 |

:::tip
所有與金鑰相關的問題都統一提示「無效的令牌」，不會單獨提示「已過期」。排查時請逐一檢查金鑰是否啟用、是否過期、金鑰額度是否用完。
:::

## 403：權限或餘額不足

| 錯誤訊息                         | 原因                                               | 解決方法                                      |
| -------------------------------- | -------------------------------------------------- | --------------------------------------------- |
| 用户额度不足 / 预扣费额度失败    | 帳戶餘額不足以支付本次請求                         | 到 [錢包](/wallet) 儲值                       |
| token quota is not enough        | 金鑰本身設定的額度已用完                           | 編輯金鑰調高額度，或改為無限額度              |
| 订阅额度不足或未配置订阅         | 計費偏好為「僅用會員」，但會員額度已用完或沒有會員 | 修改計費偏好，請見 [會員套餐](/subscriptions) |
| 該令牌無權存取模型 xxx           | 金鑰設定了模型限制，不包含該模型                   | 編輯金鑰的「模型限制」，或換用其他金鑰        |
| 无权访问 xxx 分组                | 目前的帳戶不能使用該分組                           | 編輯金鑰換一個可用分組                        |
| 分组 xxx 已被弃用                | 該分組已停用                                       | 編輯金鑰換一個可用分組                        |
| 您的 IP 不在令牌允许访问的列表中 | 金鑰設定了 IP 白名單                               | 把目前的 IP 加入白名單，或清空白名單          |
| 使用者已被封禁                   | 帳戶被停用                                         | 聯絡站點管理員                                |

## 400：請求參數有誤

| 錯誤訊息                         | 原因                        | 解決方法          |
| -------------------------------- | --------------------------- | ----------------- |
| 未指定模型名稱，模型名稱不能為空 | 請求內容中沒有 `model` 欄位 | 補上 `model` 參數 |

其他 400 錯誤通常來自上游對參數的校驗，請根據 `message` 調整參數。

## 429：請求過於頻繁

| 錯誤訊息                             | 原因                         | 解決方法                                                |
| ------------------------------------ | ---------------------------- | ------------------------------------------------------- |
| 您已達到請求數限制                   | 超過了模型的請求頻率限制     | 降低請求頻率後重試                                      |
| 请求次数已达到当前会员套餐的窗口上限 | 超過了會員套餐的請求次數上限 | 等待時間窗口重設，回應標頭 `Retry-After` 會給出等待秒數 |
| 并发请求数已达到当前套餐上限         | 同時進行的請求太多           | 減少並行數，或升級更高級別的會員套餐                    |
| （空的回應內容）                     | 觸發了全站限流               | 按 `Retry-After` 等待後重試                             |

## 503：暫無可用線路

| 錯誤訊息                       | 原因                                               | 解決方法                                                                           |
| ------------------------------ | -------------------------------------------------- | ---------------------------------------------------------------------------------- |
| 分組 xxx 下模型 xxx 無可用管道 | 該分組暫時沒有能提供這個模型的線路，或模型名稱寫錯 | 檢查模型名稱拼寫；到 [模型廣場](/pricing) 確認該模型在你的分組中可用；或換一個分組 |

## 仍然無法解決？

請記下回傳訊息中的 **request id**，聯絡站點管理員並提供該識別碼，便於快速定位問題。
