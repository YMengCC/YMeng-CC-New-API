На этой странице описано две вещи: как узнать, что именно израсходовал конкретный запрос, и какие ограничения частоты действуют на {{SYSTEM_NAME}}.

## Расход одного запроса

### В консоли

Откройте [Журнал использования](/usage-logs/common): каждая строка — один вызов API.

| Столбец                | Значение                                                                                        |
| ---------------------- | ----------------------------------------------------------------------------------------------- |
| Tokens                 | Показывается как `вход / выход`. Если запрос использовал кэш, ниже указаны чтения и записи кэша |
| Стоимость              | Сумма, фактически списанная за этот запрос, в валюте сайта                                      |
| Модель / Ключ / Группа | Модель, ключ API и группа, обработавшие запрос                                                  |
| Время                  | Длительность в секундах и признак потокового ответа                                             |

Щёлкните по строке, чтобы открыть подробности: способ тарификации, применённая цена за единицу, разбивка оплачиваемых токенов и попадания в кэш.

### По идентификатору запроса

Каждый ответ API содержит идентификатор в заголовке:

```http
X-Oneapi-Request-Id: <идентификатор запроса>
```

По нему можно получить запись журнала этого запроса:

```bash
curl {{BASE_URL}}/api/log/self?request_id=REQUEST_ID \
  -H "Authorization: Bearer YOUR_ACCESS_TOKEN"
```

`request_id` уникален, поэтому в `data.items` обычно одна запись:

```json
{
  "success": true,
  "data": {
    "items": [
      {
        "created_at": 1761177600,
        "type": 2,
        "model_name": "claude-sonnet-5-5",
        "token_name": "my-key",
        "group": "default",
        "prompt_tokens": 1520,
        "completion_tokens": 380,
        "quota": 1450,
        "use_time": 3,
        "is_stream": true,
        "request_id": "20261023xxxxxxxx"
      }
    ],
    "total": 1
  }
}
```

Этому эндпоинту нужна активная сессия или токен доступа, созданный на странице аккаунта. Ключ API вида `sk-` его вызвать не может — используйте способ ниже.

### Если есть только ключ API

Если у вас только ключ, без входа в аккаунт:

```bash
curl {{BASE_URL}}/api/log/token \
  -H "Authorization: Bearer YOUR_API_KEY"
```

Эндпоинт возвращает **1000 последних записей** этого ключа. Фильтр по `request_id` не поддерживается: сопоставьте полученный заголовок `X-Oneapi-Request-Id` с результатами самостоятельно.

### Перевод квоты в сумму

Полезные поля:

| Поле                | Значение                                            |
| ------------------- | --------------------------------------------------- |
| `prompt_tokens`     | Входные токены                                      |
| `completion_tokens` | Выходные токены                                     |
| `quota`             | Списание за запрос, во внутренних единицах          |
| `use_time`          | Длительность в секундах                             |
| `type`              | `2` расход, `1` пополнение, `5` ошибка, `6` возврат |

`quota` пересчитывается на странице автоматически. Соотношение такое:

```text
сумма (USD) = quota / 500000
отображаемая сумма = сумма (USD) × курс сайта
```

Например, `quota = 1450` — это `0,0029` USD. Входные токены из кэша обычно тарифицируются по более низкой цене; точная цена указана в подробностях.

:::tip
Если нужны только счётчики токенов, вызывать журнал не обязательно: в непотоковых ответах есть объект `usage`; для потоковых добавьте `"stream_options": {"include_usage": true}`, и последний chunk будет содержать `usage`. Фактически списанную сумму можно узнать только из журнала.
:::

## Ограничения частоты запросов

### Консоль и API

| Где                                                                                            | Считается по              | Окно        | Предел       |
| ---------------------------------------------------------------------------------------------- | ------------------------- | ----------- | ------------ |
| Вызовы API консоли                                                                             | IP                        | 180 секунд  | 360 запросов |
| Страницы консоли                                                                               | IP                        | 180 секунд  | 120 запросов |
| Чувствительные действия (вход, регистрация, сброс пароля, оплата, привязка почты или телефона) | IP                        | 1200 секунд | 20 запросов  |
| Чувствительные действия                                                                        | Аккаунт, по типу действия | 1200 секунд | 20 запросов  |
| Поиск (ключи, журналы)                                                                         | Аккаунт                   | 60 секунд   | 10 запросов  |
| Коды подтверждения по почте                                                                    | IP                        | 30 секунд   | 2 запроса    |

Несколько уточнений:

- Это значения по умолчанию; их могут менять по эксплуатационным причинам, ориентируйтесь на фактический ответ.
- Журнал доступен не глубже 365 дней, страница отдаёт не более 100 строк (по умолчанию 10).
- Ограничения по IP делят все, кто выходит через тот же сетевой адрес: один офис или один облачный хост.

Вызовы моделей (чат, embeddings, изображения) тарифицируются по балансу и не подпадают под счётчики выше. Отдельной квоты «запросов в минуту» для ключа API нет; при необходимости ограничивайте частоту на стороне клиента.

### При срабатывании ограничения

Запрос отклоняется с HTTP 429 и заголовком `Retry-After` в секундах:

```http
HTTP/1.1 429 Too Many Requests
Retry-After: 47
```

Подождите указанное число секунд перед повтором: немедленный повтор расходует остаток окна и продлевает блокировку.

```python
import time, requests

resp = requests.post(url, headers=headers, json=payload)
if resp.status_code == 429:
    time.sleep(int(resp.headers.get("Retry-After", 60)))
    resp = requests.post(url, headers=headers, json=payload)
```

Если списание кажется двойным, сначала проверьте, нет ли в журнале двух строк с одинаковым `request_id`, и при наличии свяжитесь с администратором сайта с этим идентификатором.
