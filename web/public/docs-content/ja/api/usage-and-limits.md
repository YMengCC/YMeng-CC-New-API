このページでは、ある 1 回のリクエストが何を消費したかを調べる方法と、{{SYSTEM_NAME}} で適用されるリクエスト頻度制限について説明します。

## 1 回のリクエストの使用量を確認する

### コンソールで確認する

[使用ログ](/usage-logs/common) を開くと、1 行が 1 回の API 呼び出しに対応しています。

| 列                       | 説明                                                                                                                   |
| ------------------------ | ---------------------------------------------------------------------------------------------------------------------- |
| Tokens                   | `入力 / 出力` の形式で表示されます。キャッシュを使った場合は、その下にキャッシュの読み取りと書き込みの数が表示されます |
| 料金                     | このリクエストで実際に差し引かれた金額（サイトの表示通貨）                                                             |
| モデル / キー / グループ | このリクエストで使われたモデル、API キー、グループ                                                                     |
| 所要時間                 | 処理時間（秒）と、ストリーミングかどうか                                                                               |

行をクリックすると詳細が開き、課金方式、適用された単価、課金対象 token の内訳、キャッシュのヒット状況を確認できます。

### リクエスト ID で照会する

API 呼び出しのレスポンスヘッダーには、リクエスト識別子が付きます。

```http
X-Oneapi-Request-Id: <リクエスト ID>
```

これを使って、その 1 件のレコードを取得できます。

```bash
curl {{BASE_URL}}/api/log/self?request_id=REQUEST_ID \
  -H "Authorization: Bearer YOUR_ACCESS_TOKEN"
```

`request_id` は一意なので、`data.items` は通常 1 件だけです。

```json
{
  "success": true,
  "data": {
    "items": [
      {
        "created_at": 1761177600,
        "type": 2,
        "model_name": "claude-sonnet-5-5",
        "token_name": "my-key",
        "group": "default",
        "prompt_tokens": 1520,
        "completion_tokens": 380,
        "quota": 1450,
        "use_time": 3,
        "is_stream": true,
        "request_id": "20261023xxxxxxxx"
      }
    ],
    "total": 1
  }
}
```

このエンドポイントにはログイン状態またはアカウントページで発行したアクセストークンが必要です。`sk-` で始まる API キーでは呼び出せないため、次の方法を使ってください。

### API キーしかない場合

キーだけがありログインしていない場合は次のようにします。

```bash
curl {{BASE_URL}}/api/log/token \
  -H "Authorization: Bearer YOUR_API_KEY"
```

このエンドポイントはそのキーの**直近 1000 件**を返します。`request_id` による絞り込みには対応していないため、受け取った `X-Oneapi-Request-Id` と自分で照合してください。

### クォータを金額に換算する

知っておきたいフィールドは次のとおりです。

| フィールド          | 意味                                         |
| ------------------- | -------------------------------------------- |
| `prompt_tokens`     | 入力 token 数                                |
| `completion_tokens` | 出力 token 数                                |
| `quota`             | このリクエストの課金額（内部クォータ単位）   |
| `use_time`          | 所要時間（秒）                               |
| `type`              | `2` 消費、`1` チャージ、`5` エラー、`6` 返金 |

`quota` はページ上で自動的に換算されます。換算関係は次のとおりです。

```text
金額（USD） = quota / 500000
表示金額 = 金額（USD）× サイトの為替レート
```

たとえば `quota = 1450` は `0.0029` USD です。キャッシュにヒットした入力は通常より低い単価で課金されます。実際の単価は詳細画面で確認してください。

:::tip
token 数だけが必要なら、ログのエンドポイントを呼ぶ必要はありません。非ストリーミングのレスポンスには `usage` が含まれます。ストリーミングの場合は `"stream_options": {"include_usage": true}` を追加すると、最後の chunk に `usage` が付きます。実際の課金額はログからしか取得できません。
:::

## リクエスト頻度制限

### コンソールと API の制限

| 対象                                                                         | カウント単位             | 期間    | 上限   |
| ---------------------------------------------------------------------------- | ------------------------ | ------- | ------ |
| コンソールの API 呼び出し                                                    | IP                       | 180 秒  | 360 回 |
| コンソールのページ表示                                                       | IP                       | 180 秒  | 120 回 |
| 重要な操作（ログイン、登録、パスワード再設定、支払い、メールや電話の紐付け） | IP                       | 1200 秒 | 20 回  |
| 重要な操作                                                                   | アカウント、操作種別ごと | 1200 秒 | 20 回  |
| 検索（キー、ログ）                                                           | アカウント               | 60 秒   | 10 回  |
| メール認証コード                                                             | IP                       | 30 秒   | 2 回   |

補足：

- 上記はサイトの既定値で、運用の都合で調整される場合があります。実際のレスポンスが優先されます。
- ログの照会範囲は最大 365 日、1 ページの返却は最大 100 件（既定 10 件）です。
- IP 単位の制限は、同じネットワーク出口を使う全員で共有されます（同じオフィス、同じクラウドホストなど）。

チャット、埋め込み、画像などのモデル呼び出しは残高による課金で、上表のリクエスト数制限は適用されません。API キー単位の「1 分あたりのリクエスト数」設定はありません。必要であればご自身のクライアント側で制御してください。

### 制限に達したとき

リクエストは HTTP 429 で拒否され、秒単位の `Retry-After` ヘッダーが付きます。

```http
HTTP/1.1 429 Too Many Requests
Retry-After: 47
```

その秒数だけ待ってから再試行してください。すぐに再試行すると期間内の残りを消費し、ブロックが長引きます。

```python
import time, requests

resp = requests.post(url, headers=headers, json=payload)
if resp.status_code == 429:
    time.sleep(int(resp.headers.get("Retry-After", 60)))
    resp = requests.post(url, headers=headers, json=payload)
```

同じリクエストで二重に課金された疑いがある場合は、まずログに同じ `request_id` のレコードが 2 件ないか確認し、あればその識別子を添えてサイト管理者に連絡してください。
